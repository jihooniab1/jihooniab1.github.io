## Introduction
CAN bus는 **BOSCH** 에 의해 개발되었으며, **multi-master** (여러 노드가 master 가능), **message broadcast system** (bus 전체로 메시지 뿌림, message identifier 기반), **maximum signaling rate of 1M bit per second** (1초에 약 100만개의 bit를 bus에 실어 보낼 수 있음, 단 실제 data throughput은 더 작음) 와 같은 특징을 갖습니다. 

## The CAN Standard
![s1](/assets/img/posts/papers/SLOA101_1.png) <br>

CAN 통신 프로토콜인 **ISO 11898** 은 네트워크상에서 장치들이 어떻게 정보를 주고받는지를 정의합니다. 또한 OSI/ISO 모델과 대응되는 계층 구조를 가지며, 위 그림에서 볼 수 있듯이 ISO 11898은 OSI 7계층 중 최하단 두 계층인 `data-link layer`와 `physical layer`를 정의합니다.

이 중 실제 물리 매체를 통해 연결된 장치 간 통신은 `physical layer`에서 다루며, 또한 `application layer`는 **CANopen** 과 같은 상위 수준의 애플리케이션 전용 프로토콜과의 통신 링크를 제공합니다.

## Standard CAN or Extended CAN
CAN 통신은 CSMA, **carrier-sense** (전송하기 전에 bus가 사용 중인지 감지), **multiple-access** (여러 노드가 같은 bus에 접근) 프로토콜이며, **CSMA/CD+AMP** (collision detection & arbitration on message priority)의 특징을 갖습니다. 

CSMA는 버스를 공유하는 노드들이 메시지를 전송하기 전에 **CAN bus가 일정시간 동안 idle(inactive) 상태인지 확인** 하는 것을 의미하며, CD+AMP는 충돌을 **bit-wise arbitration(중재)** 를 통해 해결하는 것을 의미합니다. 

### The Bit Fields of Standard CAN and Extended CAN
![s1](/assets/img/posts/papers/SLOA101_2.png) <br>

- **SOF (Start of Frame)**: 단일 `dominant` 비트입니다. CAN에서 `dominant`는 논리 `0`, `recessive`는 논리 `1`을 의미합니다. SOF는 메시지의 시작을 나타내며, bus가 idle 상태였다가 통신을 시작할 때 노드 간 동기화에 사용됩니다.

- **Identifier**: 메시지의 우선순위를 결정합니다. Identifier의 이진수 값이 낮을수록 우선순위가 높습니다.

- **RTR (Remote Transmission Request)**: 단일 비트로, Data Frame과 Remote Frame을 구분하는 데 사용됩니다.
  - `dominant(0)`: Data Frame
  - `recessive(1)`: Remote Frame  
  Remote Frame은 특정 Identifier에 해당하는 데이터의 전송을 요청할 때 사용됩니다. 요청은 bus의 모든 노드가 수신하며, 해당 Identifier에 대응하는 노드가 Data Frame으로 응답합니다. 응답 데이터 역시 bus 전체에 broadcast되므로 필요한 모든 노드가 이를 사용할 수 있습니다.

- **IDE (Identifier Extension)**: 단일 비트입니다. `dominant(0)` 상태이면 추가 Identifier 확장이 없는 Standard CAN frame임을 나타냅니다.

- **r0**: 향후 표준 확장을 위해 예약된(reserved) 비트입니다. 이후 CAN FD에서는 Classical CAN에서 reserved였던 위치가 프로토콜 확장에 활용됩니다.

- **DLC (Data Length Code)**: 4-bit 필드로, 전송되는 데이터의 바이트 수를 나타냅니다.

- **Data**: 최대 64-bit, 즉 8-byte의 애플리케이션 데이터를 전송할 수 있습니다.

- **CRC (Cyclic Redundancy Check)**: 총 16-bit로 구성되며, 15-bit의 CRC sequence와 1-bit의 CRC delimiter로 이루어집니다. CRC는 앞서 전송된 비트열을 기반으로 계산된 값을 이용해 전송 과정에서 발생한 오류를 검출하는 데 사용됩니다.

- **ACK (Acknowledgement)**: 메시지를 정상적으로 수신한 노드는 송신자가 `recessive` 상태로 전송한 ACK slot을 `dominant`로 덮어써 정상 수신되었음을 나타냅니다. 송신자가 `dominant` ACK를 확인하지 못하면 arbitration을 다시 거친 뒤 메시지를 재전송합니다. ACK field는 ACK slot과 ACK delimiter를 합쳐 총 2-bit로 구성됩니다.

- **EOF (End of Frame)**: 7개의 `recessive` bit로 구성되며 CAN frame의 끝을 나타냅니다. EOF 구간에서는 **bit stuffing**이 적용되지 않으며, 이 구간에서 `dominant` bit가 검출되면 frame 형식 오류(form error)로 처리됩니다.

- **Bit Stuffing**: 같은 logic level의 bit가 5개 연속되면 반대 logic level의 bit 1개를 자동으로 삽입하는 방식입니다. 수신 측 CAN controller는 삽입된 stuff bit를 제거한 뒤 원래 bit stream을 해석합니다. 이를 통해 긴 시간 동안 signal transition이 사라지는 것을 방지하여 노드 간 synchronization을 유지하는 데 도움을 줍니다.

- **IFS (Inter-Frame Space)**: 하나의 frame이 끝난 뒤 다음 frame이 시작되기 전까지의 간격을 제공하는 영역입니다. 수신 controller가 정상적으로 수신한 frame을 message buffer로 옮기고 다음 frame을 처리할 수 있도록 시간을 제공합니다.

![s1](/assets/img/posts/papers/SLOA101_3.png) <br>

Extended CAN은 **29-bit Identifier**(11-bit base ID + 18-bit extension) 를 사용합니다. 18-bit extension 필드는 IDE 필드 뒤에 옵니다. SRR은 Extended CAN에서 Standard CAN의 RTR 자리와 호환되도록 넣은 recessive 비트이고, 11-bit base ID가 경쟁할 때 Standard frame이 우선하도록 합니다. 

## A CAN Message
### Arbitration
![s1](/assets/img/posts/papers/SLOA101_4.png) <br>

위 그림에서 확인할 수 있듯이, CAN transceiver의 driver는 controller에서 전달된 디지털 신호를 CANH/CANL을 통해 bus에 출력하고, receiver는 실제 CANH/CANL의 bus 상태를 읽어 다시 디지털 신호로 전달합니다. CAN에서는 dominant(0)와 recessive(1) 두 상태를 사용하며, 명확한 입력이 없는 경우 **transceiver의 driver input과 receiver output** 은 내부적으로 **high로 pull-up** 되어 기본적으로 recessive 상태를 갖습니다.

버스 접근은 event-driven으로, 랜덤하게 발생할 수 있습니다. 두 노드가 동시에 메시지 전송을 시작할 때, 이 접근은 nondestructive, bit-wise arbitration으로 구현되어있습니다. 이때 nondestructive는 중재에서 이긴 노드의 메시지는 그대로 이어진다는 것을 의미합니다. 

CAN에서는 메시지의 Identifier 값이 낮을수록 더 높은 우선순위를 가집니다. CAN bus에서는 dominant(0) bit가 recessive(1) bit보다 우선하므로, 두 노드가 동시에 전송을 시작했을 때 동일한 bit 위치에서 한 노드가 dominant bit를, 다른 노드가 recessive bit를 전송하면 bus에는 dominant bit가 나타납니다. 이때 recessive bit를 전송한 노드는 자신이 전송한 값과 bus에서 읽은 값이 다름을 감지하고 arbitration에서 탈락하며, dominant bit를 전송한 노드는 계속 전송합니다. <br>

![s1](/assets/img/posts/papers/SLOA101_5.png) <br>

위 그림은 중재 과정을 나타냅니다. 각 노드는 각자 전송한 메시지를 계속 모니터링하고 있기 때문에, 노드 B는 자신이 전송한 recessive bit와 실제 bus에서 읽은 dominant bit가 다름을 감지하면 arbitration에서 패배했다고 판단하여 전송을 중단합니다. 이후 노드 C가 bus를 release하면 다시 arbitration에 참여하여 전송을 시도합니다. 이러한 중재 동작은 ISO 11898의 `physical signaling layer`에 포함된 기능으로, **CAN controller 내부에서 자동으로 처리** 됩니다. 따라서 상위 소프트웨어나 CAN 사용자가 bit 단위의 arbitration 과정을 직접 구현할 필요는 없습니다.

### Message Types
#### The Data Frame
가장 흔한 메시지 유형으로 arbitration field, data field, CRC field, ACK field로 구성됩니다. Arbitration field는 두 개 이상의 노드가 동시에 bus 접근을 시도할 때 메시지의 우선순위를 결정하는 영역으로, CAN 2.0A에서는 11-bit identifier와 dominant(0) 상태인 RTR bit로 구성됩니다. Data field는 실제 전송하려는 데이터를 포함하며, CRC field에는 전송 과정에서 발생한 오류를 검출하기 위한 16-bit CRC가 포함됩니다.

ACK field에는 메시지를 정상적으로 수신한 CAN controller가 송신자가 recessive(1)로 전송한 ACK bit를 dominant(0)로 덮어씁니다. 송신 노드는 dominant ACK bit를 관측하지 못하면 재전송합니다. 

#### The Remote Frame
Remote frame은 다른 노드에게 데이터 전송을 요청하기 위한 프레임으로, Data frame과 구조가 유사하지만 i) recessive(1) RTR bit를 통해 Remote frame임을 나타내며, ii) data field가 없습니다. CAN fd에는 이러한 프레임이 없고 그냥 페이로드를 해석하는 상위 프로토콜이 누가 요청이고 응답인지 결정한다고도 합니다.

#### The Error Frame
에러 프레임은 CAN 메시지의 **정상적인 formatting rule을 의도적으로 위반하는 특수 프레임** 으로, 어떤 노드가 메시지에서 오류를 검출했을 때 발생하며, 어떤 노드가 오류를 검출하여 Error Frame을 전송하면, 다른 노드들도 이를 오류로 인식하고 Error Frame을 발생시킵니다. 이후 원래 메시지를 전송하던 노드는 해당 메시지를 다시 전송합니다.

#### The Overload Frame
수신 노드가 다음 frame을 즉시 처리하기 어려운 경우 frame 사이에 추가적인 지연을 제공하기 위한 특수 프레임입니다.

### A Valid Frame
CAN 메시지는 EOF field의 마지막 bit까지 정상적인 recessive 상태로 수신되었을 때 정상적으로 완료된 frame으로 간주됩니다. EOF 구간에서 dominant bit가 검출되면 frame 형식 오류로 처리되며, 송신 노드는 해당 메시지를 다시 전송합니다.

### Error Checking and Fault Confinement
CAN 프로토콜에는 에러를 체크하는 5개의 방법이 있는데, 이 중 하나라도 메시지 에러를 감지하면 수신 노드는 에러 프레임을 생성합니다. 문제를 계속 일으키는 node의 CAN controller는 error counter가 한계에 도달하면 node의 송신 기능을 제한해버립니다.

메시지 레벨에는 세가지 방법이 있습니다: **CRC, ACK, form check**. CRC 필드는 애플리케이션 데이터의 체크섬을 포함하며, ACK 필드는  송신자가 자신의 프레임을 정상적으로 받은 노드가 있는지 확인하는데 사용됩니다. Form check는 EOF, ACK delimiter, CRC delimiter처럼 항상 recessive(1)여야 하는 비트를 체크하여 dominant(0) 비트가 있으면 에러를 생성합니다.

비트 레벨에서 송신 노드는 **자신이 전송한 각 bit** 와 **실제 bus에서 읽은 bit** 를 비교합니다. 일반적인 전송 구간에서 두 값이 다르면 bit error가 발생합니다. 일반적인 송신 구간에서 송신 bit와 bus에서 읽은 bit가 다르면 bit error가 발생하며, **arbitration에 사용되는 영역과 ACK slot은 예외** 입니다.

마지막 에러 탐지 방법은 **bit-stuffing** 으로 동일한 logic level의 bit가 5개 연속될 경우 반대 logic level의 stuff bit를 하나 삽입하는 방식입니다. 수신 CAN controller는 삽입된 stuff bit를 제거하여 원래 bit stream을 복원합니다. 만약 동일한 bit가 5개 연속된 뒤 반대 bit가 나타나지 않으면 stuffing error로 처리됩니다. 이러한 방식은 **주기적으로 signal transition을 발생시켜 노드 간 synchronization을 유지** 하고, 정상 데이터의 연속 bit pattern이 **Error Frame이나 interframe space와 혼동되는 것을 방지** 하는 데 도움을 줍니다.

## The CAN Bus
![s1](/assets/img/posts/papers/SLOA101_6.png) <br>

CAN의 data-link layer와 physical signaling layer는 CAN 프로토콜을 구현하는 **CAN controller 내부에 포함** 됩니다. CAN controller와 실제 물리 매체인 CAN bus 사이의 연결은 CAN transceiver를 통해 구현되며, 이들이 함께 하나의 CAN node를 구성합니다.

CAN bus는 **CANH와 CANL 두 선을 이용한 differential signaling(차동 신호)** 을 사용합니다. 두 신호선에는 서로 반대 방향의 신호 변화가 나타나며, 이를 통해 외부로 방사되는 노이즈를 줄이고 두 선에 공통으로 유입되는 common-mode noise의 영향을 억제할 수 있습니다. 이러한 특성은 전기적 노이즈가 많은 자동차 및 산업 환경에서 CAN의 높은 안정성에 기여합니다.

ISO 11898 표준에 따르면 CAN bus는 일반적으로 **120Ω characteristic impedance를 갖는 twisted-pair 케이블을 사용** 합니다. Bus의 양 끝에는 각각 **120Ω termination resistor를 배치** 하며, 이는 **전송선(CANH+CANL)의 characteristic impedance(임피던스: 전기 신호가 흐르기 어려운 정도, 케이블 자체가 갖는 고유한 임피던스)와 맞춰** 신호 반사를 줄이기 위한 것입니다. <br>
